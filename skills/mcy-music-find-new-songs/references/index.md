# Обновление локального индекса

Используй `scripts/song_index.py` на Python 3.10+; все зависимости входят в
стандартную библиотеку. Ассистент читает Google Sheets, Drive и другие источники
через доступные подключенные инструменты. Скрипт принимает полученные данные
в JSON, сравнивает версии и управляет SQLite; собственная авторизация API
и отдельный сервер ему не нужны.

## Где хранится база

При первой команде start база создается автоматически отдельно для пользователя
и профиля библиотеки. Настройка вручную обычно не требуется:

- macOS: `~/Library/Application Support/church-skills/song-discovery/<профиль>/index.sqlite3`;
- Linux: `$XDG_DATA_HOME/church-skills/song-discovery/<профиль>/index.sqlite3`
  или `~/.local/share/church-skills/song-discovery/<профиль>/index.sqlite3`;
- Windows: `%LOCALAPPDATA%/church-skills/song-discovery/<профиль>/index.sqlite3`.

Профиль — короткий хеш идентификатора библиотеки и листов. Другую библиотеку
отделяй глобальным параметром --profile, например идентификатором ее таблицы
и листа источников. Глобальный --db или переменная SONG_DISCOVERY_DB позволяют
задать другой файл, например в изолированном рабочем каталоге для теста.
Глобальные параметры указываются **перед** именем команды. В Windows вместо
python3 может использоваться python.

База содержит тексты и результаты анализа и остается локальной. Не клади ее
в репозиторий, каталог установленного скилла или выдаваемый пользователю архив.
Установка и обновление скилла сохраняют пользовательскую базу. Несовместимую
схему скрипт отвергает с ошибкой, не пересоздавая ее с потерей данных.

## 1. Начни запуск со свежими данными

Полностью прочитай живой лист источников и текущую собственную библиотеку.
Запиши JSON во временный рабочий файл, например run.json:

```json
{
  "sources_complete": true,
  "sources": [
    {"name": "Название общины", "type": "Библиотека", "url": "https://example.org/music"}
  ],
  "library_complete": true,
  "library": [
    {"id": "0:2", "title": "Название нашей песни", "lyrics": "Полный текст из таблицы", "complete": true}
  ]
}
```

Это пример формы, не источник для реального подбора. id собственной песни может
быть идентификатором листа и строки. Строки только с заранее заполненным номером
не включай. sources_complete разрешено ставить в true только после чтения всего
реестра; частичный реестр скрипт отклонит. library_complete означает чтение всех
строк библиотеки, а complete у песни — полноту именно ее текста. При отсутствии
свежей собственной библиотеки передай library_complete: false; результат сверки
будет предварительным.

```bash
python3 "<skill-dir>/scripts/song_index.py" start --input run.json
```

Сохрани run_id и source id из ответа. Скрипт объединяет повторные ссылки,
исключает оба типа «Приложение»/«Приложения» и отключает источники, исчезнувшие
из свежего реестра. Старые тексты не считаются актуальными до проверки в новом
запуске. Содержимое свежего снимка своей библиотеки понадобится также для
смысловой проверки возможных дублей.

## 2. Получи состав каждого разрешенного источника

Прочитай метаданные всех подходящих документов, включая подпапки и страницы
выдачи. Для Drive item id — постоянный ID файла, для YouTube — ID видео,
для сайта — устойчивый адрес страницы песни. Один PDF/сборник является одним
документом и может содержать много песен. Не разбивай его на фиктивные файлы
с выдуманными датами изменения.

revision — надежная версия **самого документа**, например версия Drive или
время изменения файла, подтвержденный ETag страницы/субтитров. Для составной
версии сформируй стабильную строку из проверенных полей. Время изменения папки,
число файлов, название, размер или дата добавления видео в плейлист не доказывают
неизменность текста. При отсутствии надежной версии передай null: тогда нужно
перечитать содержание и сравнить текст, сохранив прежний анализ при совпадении.

Собери все страницы в inventory.json:

```json
{
  "complete": true,
  "items": [
    {"id": "stable-file-id", "title": "Название файла", "url": "https://example.org/music/song", "revision": "confirmed-version-1"}
  ]
}
```

```bash
python3 "<skill-dir>/scripts/song_index.py" plan --run RUN --source SOURCE --input inventory.json
```

Читай содержание только документов из read_required. Остальные проверены
по текущей версии и используют сохраненные тексты. В первом запуске этот список
содержит все еще не прочитанные документы, в следующих — новые, измененные,
неполностью прочитанные или не имеющие надежной версии.

complete: true означает **полный состав источника**, а не последнюю страницу
выдачи. Только такой снимок позволяет исключить исчезнувшие документы. При
усечении, недоступной подпапке или ошибке перечисления используй complete: false,
сохрани известные позиции и явно сообщи о частичном охвате. Не принимай ошибку
списка за полный пустой каталог. При продолжении передай объединенный актуальный
список, а не только добавочную страницу.

## 3. Обнови тексты и смысловые описания

Для каждого read_required прочитай источник и сохрани **все** извлеченные из этого
документа песни через put. Для большого сборника songs содержит весь его набор:
после успешного импорта прежний набор заменяется атомарно. Если обработана лишь
часть сборника, не передавай ее как весь документ: отметь fail и продолжи чтение.

```json
{
  "revision": "confirmed-version-1",
  "songs": [
    {
      "key": "page-12-song-1",
      "title": "Название песни",
      "author": "Подтвержденный автор",
      "lyrics": "Полный извлеченный текст",
      "complete": true,
      "links": ["https://example.org/music/song"]
    }
  ]
}
```

```bash
python3 "<skill-dir>/scripts/song_index.py" put --run RUN --source SOURCE --item ITEM --input document.json
```

key — уникальная позиция песни внутри документа, например страница/номер; если
он не указан, используется хеш нормализованного текста. revision должна совпадать
с plan. При изменении файла во время чтения перепроверь метаданные и план.
При ошибке, недоступном OCR или отсутствии полного текста не выдавай пустой
songs за успешно прочитанный документ:

```bash
python3 "<skill-dir>/scripts/song_index.py" fail --run RUN --source SOURCE --item ITEM --reason "Не удалось извлечь полный текст"
```

Если в документе действительно нет песен и это проверено чтением, songs: []
является допустимым результатом. Явно неполный текст можно сохранить с complete:
false, но он не попадет в подтвержденный подбор. Старое содержимое при ошибке
остается в базе и не выдается как свежее.

put возвращает analysis_needed. Сначала сохрани извлеченные тексты, затем
проанализируй только новые/измененные тексты: основную мысль и смысловые темы.
При совпадении нормализованного текста прежний анализ сохраняется даже после
изменения версии сборника или обнаружения копии в другом источнике.

```bash
python3 "<skill-dir>/scripts/song_index.py" get --run RUN --song SONG
```

После чтения полного текста передай проверенный lyrics_hash из ответа:

```json
{"lyrics_hash": "HASH_FROM_GET", "summary": "Главная мысль песни, выведенная из полного текста", "topics": ["Смысловая тема"]}
```

```bash
python3 "<skill-dir>/scripts/song_index.py" analyze --song SONG --input analysis.json
```

Если анализ относится к старому тексту, скрипт отклонит его. После прерванного
предыдущего запуска проверь также analysis_needed в компактном каталоге:
необработанные тексты могли уже сохраниться без описаний. Анализируй одинаковый
текст один раз, используя объединенные записи каталога.

## 4. Выбери песни по смыслу

```bash
python3 "<skill-dir>/scripts/song_index.py" catalog --run RUN --limit 100
python3 "<skill-dir>/scripts/song_index.py" catalog --run RUN --limit 100 --offset NEXT_OFFSET
```

Прочитай **все страницы** компактного каталога текущего запуска. Он содержит
названия, главные мысли, темы и ссылки; полные тексты бери через get для анализа
новых песен и проверки итоговых кандидатов. SQLite хранит содержание, а смысловой
отбор выполняет ассистент. Отдельного сервиса embeddings здесь нет.

query — необязательное ускорение по словам в названиях/описаниях/темах;
оно не является семантическим поиском и не должно ограничивать итоговый набор
только совпавшими словами. Число записей и next_offset позволяют проверить охват.

Точные дубли нормализованных текстов объединяются, совпадения со свежей собственной
библиотекой исключаются. possible_library_matches указывает совпадения названий;
это повод сверить тексты, а не автоматически исключать разные песни. Переводы,
новые куплеты и близкие версии дополнительно сравни со свежим снимком библиотеки.
library_check_ready подтверждает полноту данных для сравнения, а не новизну
всех оставшихся песен.

```bash
python3 "<skill-dir>/scripts/song_index.py" status --run RUN
```

Перед ответом проверь coverage_complete, статусы источников, неполные тексты
и library_check_ready из catalog. При неполном обновлении выдавай только текущие
проверенные находки, обозначай пропуски и не утверждай, что весь архив просмотрен.
SQLite и временные JSON с текстами остаются локальными; пользователь получает
подбор песен со ссылками, а не дамп индекса.
