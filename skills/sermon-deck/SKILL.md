# Sermon Deck

Пастор отдаёт конспект в PDF, из него нужно собрать колоду в том же стиле, что и десятки уже сделанных презентаций, лежащих рядом.

## Три требования, которые задают всё остальное

Проецируемая площадь в зале маленькая, и это диктует форму:

- **На слайде только заголовки пунктов и основные моменты.** Не пересказ конспекта. Конспект целиком уходит в комментарии докладчика (см. ниже).
- **Текст как можно крупнее.** Если формулировка не влезает в строку — сокращай формулировку, а не кегль. Пункт из 3–4 слов лучше, чем из 7 мелким шрифтом.
- **Фон обязательно чёрный.** При показе он выглядит прозрачным. Это не тема слайда, а чёрный прямоугольник на всю площадь на каждом слайде — так сделано в референсах, и `deckbuilder` кладёт его сам.

## Пути к ресурсам

Все пути `scripts/`, `assets/` и `references/` относятся к папке этого скилла,
а не к текущей рабочей папке. Перед запуском найди абсолютный путь к установленному
`sermon-deck` и используй его в командах. Сборку и результаты сохраняй в папке
пользователя с конспектом, а не внутри установленного скилла.

Пример из `references/example_build.py` запускается без правки путей:

```bash
uv run /путь/к/sermon-deck/references/example_build.py --output Проповедь.pptx
```

Если копируешь пример в `build.py` рядом с конспектом, передай
`--skill-dir /путь/к/sermon-deck`. Замени учебное содержимое на конспект пользователя.

## Порядок работы

**1. Найди конспект.** PDF с конспектом проповеди — этого достаточно: шаблон стиля вшит в скилл (`assets/template.pptx`), папка с готовыми презентациями не нужна.

Если она всё-таки под рукой (обычно «Референсные презентации» рядом с конспектом) — передай её в `newest_template(folder)`: возьмётся самый свежий файл. Стиль общины со временем меняется, и свежая презентация точнее вшитой. Свежесть определяется по `dcterms:modified` в `docProps/core.xml` — даты записей в zip у этих файлов затёрты, по ним не ориентируйся.

**2. Разбери конспект:**

```bash
uv run scripts/outline.py конспект.pdf
```

Скрипт печатает структуру. Вывод `outline.py` сокращает длинные абзацы для обзора; полный текст для заметок извлеки отдельно через `pdftotext -layout конспект.pdf -` или чтение PDF. **Жирный шрифт в конспекте — это пункты, которые пастор выделил как ключевые**; они и становятся разделами колоды. Обычные абзацы между ними — материал для пунктов списка и для заметок. Внизу — список всех ссылок на Писание.

Заголовок, не выделенный жирным (в разборе он попадёт в текст абзаца), — подпункт: его логичнее свернуть в пункт списка соседнего раздела, а не делать отдельным разделом.

**3. Продумай колоду.** Каждый слайд должен помогать следить за мыслью проповеди. Ориентир — 9–15 слайдов на 3–5 разделов; больше разделов — пропорционально больше. Не делай отдельный экран на каждый абзац конспекта. Убирай повторные определения, пустые лозунги и фразы без достаточного контекста вроде «Новые отношения с Богом». Объединяй их с объясняющим списком либо оставляй в заметках. Повторный или дополнительный материал после выводов не запускает вторую презентацию: сохрани его в заметках к подходящим слайдам или к итоговому слайду. Собери из типов:

| Тип | Когда |
|---|---|
| `title` | Первый слайд: название капсом жёлтым, подзаголовок белым, ниже ссылка на ключевой текст |
| `divider` | Начало раздела: римская цифра в жёлтом круге + заголовок раздела |
| `bullets` | Сразу после разделителя: 3–4 пункта, над ними жёлтая плашка `> НАЗВАНИЕ РАЗДЕЛА` |
| `statement` | Одна сильная мысль на весь слайд, часть строки можно выделить жёлтым |
| `callout` | Плашка `> ВАЖНО!` и развёрнутая мысль под ней |
| `verse` | Цитата: крупные серые кавычки на фоне, белый текст, жёлтая ссылка справа внизу |
| `poem` | Куплет гимна в конце |

По умолчанию выводы собери на одном содержательном слайде. **Нарастание** перечня используй, когда оно помогает устной подаче или прямо запрошено; не размножай одинаковые итоговые экраны автоматически. Для нарастания передавай `all_items=` и `top_in=1.70`, чтобы кегль и верх блока не прыгали.

**4. Собери.** Напиши для конкретной проповеди небольшой `build.py`, который зовёт `Deck` — см. `references/example_build.py`. Библиотека сама подбирает самый крупный кегль, который влезает, и считает высоты рамок.

**5. Проверь:**

```bash
uv run scripts/check.py Проповедь.pptx render/
```

Скрипт сначала проверяет пакет PPTX: XML, связи и объявления префиксов в значениях `xsi:type`. Затем ищет вылезания текста, отсутствие фона, логотипа или заметок, рендерит в PDF и PNG и проверяет реальные окончания строк на висячие предлоги. **Посмотри PNG глазами** — расчёт кегля надёжный, но разделители с длинными словами и самые плотные списки стоит увидеть. Если доступен PowerPoint, открой в нём готовый PPTX и убедись, что он не требует Repair: успешный рендер LibreOffice этого не гарантирует. PDF отдай вместе с pptx: на служении это запасной вариант.

**6. Отдай файл** рядом с конспектом, названием по теме проповеди (как в папке референсов: «Смысл и значение Пасхи.pptx»).

## Формулировки пунктов

Пункты — это опоры для устной речи, а не тезисы. В референсах они звучат так: «Рабство и суд», «Агнец вместо первенца», «Читай Писание вдумчиво». Ориентир — одна строка при кегле 60pt, это примерно 40 знаков.

Если не влезает, переформулируй короче:

- «Непослушание закону — выпад против Самого Бога» → «Непослушание закону – бунт»
- «Жертва должна была быть безупречной» → «Безупречная жертва»
- «Выкуп заплачен Богу, а не дьяволу» → «Выкуп – Богу, а не дьяволу»

Заголовки разделов и текст на слайдах — капсом; в плашке `> …` капс ставится автоматически.

На экране используй **е вместо ё**, в том числе в цитатах; исходный текст в заметках сохраняй дословно. Предлоги связывай со следующим словом неразрывным пробелом: «СО ХРИСТОМ», «С БОГОМ». `Deck` делает это автоматически, а расчёт ширин учитывает связанные слова. Не оставляй предлог перед явным переводом строки. Для титула, заголовков разделов и крупных мыслей используется плотный интервал 0.88, для списков, пояснений и цитат — 1.05. Не увеличивай интервал всей колоды ради одного пересечения: проверяй конкретные пары строк с выносными и надстрочными элементами. Параметр `leading=` у `title`, `divider` и `statement` позволяет поправить нужный блок отдельно; высота рамки рассчитывается с тем же значением. Сокращай формулировку прежде, чем уменьшать кегль.

## Стихи Писания

Показывай основные отрывки, которые раскрывают мысль раздела или читаются вслух. Вспомогательные ссылки сохраняй в заметках; не создавай отдельный экран для каждой ссылки автоматически. Один и тот же отрывок обычно достаточно показать один раз. Полнота заметок не требует повторов на экране.

Текст берётся так:
- **Стих процитирован в конспекте** — бери оттуда дословно, это тот перевод, который будет читать пастор.
- **В конспекте только ссылка** — сверь синодальный текст по azbyka.ru (`https://azbyka.ru/biblia/?Rom.6&r`). Не приводи Писание по памяти: на экране в зале ошибка в стихе — это не опечатка, а искажение текста Писания.

Для цитат всегда используй `Deck.verse`: чёрный фон, крупные серые кавычки позади текста, белая цитата и жёлтая ссылка с выравниванием вправо внизу. У каждой фоновой кавычки два угловатых наклонных штриха, оба видны. В `Deck` это редактируемые векторные фигуры: форма не зависит от наличия Gilroy и не меняется при экспорте. Не заменяй их символом из Calibri или другого шрифта. Это оформление закреплено по образцу общины; обычная плашка `> …` здесь не нужна. Ссылку пиши коротко: «1 Петра 2:24», «Галатам 6:7–8», «Матфея 20:28». Длинный отрывок дели по смыслу, без потерь текста и без коротких хвостов на отдельном слайде. Содержание и ссылку проверяй независимо от оформления образца.

## Комментарии докладчика

Весь конспект разложи по слайдам, чтобы во время проповеди не открывать PDF отдельно. Логика простая:

- слайд-разделитель — название раздела;
- слайд со списком — абзацы конспекта, которые стоят за этими пунктами;
- слайд со стихом — фраза конспекта, которая его вводит.

Порядок фрагментов должен идти по конспекту, без пропусков. Перед сдачей проверь покрытие программно — разбей конспект на фрагменты в словаре и убедись, что каждый попал в заметки ровно один раз:

```python
allnotes = "\n".join(s.notes_slide.notes_text_frame.text for s in prs.slides)
missing = [k for k, v in FRAGMENTS.items() if v.strip() not in allnotes]
```

## Собирай только через API python-pptx

`deckbuilder` работает через API: библиотека сама формирует `[Content_Types].xml`, связи и `presentation.xml`. **Не пиши XML слайдов строками и не правь части пакета регулярками.**

API сохраняет и повреждения исходного шаблона. В прежнем `assets/template.pptx` метаданные даты содержали `xsi:type="dcterms:W3CDTF"`, но префикс `dcterms` не был объявлен: сериализация XML переименовала объявление, не изменив QName в значении атрибута. PowerPoint требовал Repair и у самого шаблона, и у собранных из него колод; LibreOffice и python-pptx открывали их без ошибки. Шаблон исправлен пересохранением в PowerPoint с сохранением логотипа и встроенных шрифтов. `Deck` теперь проверяет шаблон до загрузки и результат после сохранения, а `check.py` останавливается при такой ошибке. Не пересериализуй метаданные через ElementTree без сохранения пространств имён QName-значений. Эта проверка ловит известный дефект, но не заменяет открытие в PowerPoint.

Если нужного API нет (нумерация `buAutoNum`, `marL`/`indent`), дописывай отдельные элементы в уже созданное библиотекой дерево — как это сделано в `Deck._numbered`. Порядок детей `a:pPr` задан схемой: `lnSpc`, `spcBef`, `spcAft`, `buClr`, `buSzPct`, `buAutoNum`.

## Файлы

- `scripts/outline.py` — разбор PDF-конспекта: жирные заголовки, абзацы, ссылки на Писание
- `scripts/deckbuilder.py` — класс `Deck`: типы слайдов, геометрия, подбор кегля, заметки
- `scripts/textmetrics.py` — ширины строк по вшитым метрикам шрифтов
- `scripts/typography.py` — экранное е и неразрывные сочетания предлогов
- `scripts/check.py` — аудит готового файла + рендер в PDF/PNG
- `scripts/packagecheck.py` — проверка пакета и QName-префиксов без изменения файла
- `references/example_build.py` — образец сборки конкретной проповеди
- `assets/template.pptx` — шаблон стиля со вшитыми шрифтами и логотипом
- `assets/font_metrics.json` — ширины символов, чтобы считать размеры без установленных шрифтов
- `references/style.md` — замеры стиля: шрифты, цвета, координаты рамок, кегли. Читай, если нужно отойти от готовых типов слайдов или разобраться, откуда взялись числа
- `tests/test_packagecheck.py` — регрессия повреждённых метаданных и сохранности содержимого
- `tests/test_typography.py` — переносы, интервал, цитаты и неизменность исходных заметок

## Запуск и зависимости

Всё запускается через `uv run` — зависимости объявлены прямо в скриптах (PEP 723) и ставятся сами, в систему ничего добавлять не надо:

```bash
uv run scripts/outline.py конспект.pdf
uv run scripts/check.py Проповедь.pptx render/
uv run build.py                      # свой файл сборки, см. references/example_build.py
```

Свой `build.py` начни с этой шапки, иначе `uv` не поставит python-pptx:

```python
# /// script
# requires-python = ">=3.10"
# dependencies = ["python-pptx"]
# ///
```

Если `uv` нет — подойдёт Python 3.10+ с установленным `python-pptx` (`python -m pip install python-pptx`). Для необязательного чтения метрик из локальных файлов шрифтов нужен также `fonttools`.

Из системного нужны `pdftohtml` (poppler) для разбора конспекта и LibreOffice для рендера в PDF — оба используются только своими шагами, сборка колоды без них работает. Для PNG нужен также `pdftoppm` из poppler. LibreOffice ищется в `PATH` и стандартной папке приложения macOS; для нестандартного пути задай переменную `SOFFICE`. Если проверка или рендер не прошли, `check.py` завершится с ненулевым кодом: исправь проблему перед сдачей.

Фирменные шрифты в системе **не обязательны**: ширины строк считаются по `assets/font_metrics.json`, а в сам шаблон шрифты вшиты, поэтому презентация верно откроется и на чужой машине. Если шрифты установлены и нужен шрифт, которого нет в JSON, `textmetrics` подхватит его из `~/Library/Fonts` через `fontTools`.
