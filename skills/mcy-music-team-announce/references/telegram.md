# Отправка с личного аккаунта Telegram

Читай этот файл, когда пользователь просит подключить Telegram, отправить анонс
или проверить отправку. Для подготовки текста подключение не нужно.

Скрипт `scripts/telegram_send.py` использует Telethon 1.45 и MTProto.
Запускай через `uv run <skill-dir>/scripts/telegram_send.py ...`: зависимости
описаны в самом файле. Не используй Bot API для выдачи отправки за личный аккаунт.

## Локальный вход

```bash
uv run <skill-dir>/scripts/telegram_send.py login --open-browser
uv run <skill-dir>/scripts/telegram_send.py status
```

`login` открывает локальную страницу. Если ключей приложения еще нет, пользователь
вводит свои `api_id` и `api_hash` из [my.telegram.org/apps](https://my.telegram.org/apps)
в этой форме. Ключи можно передать окружением `TELEGRAM_API_ID` и
`TELEGRAM_API_HASH`. Затем пользователь сканирует QR-код через Telegram на телефоне:
Настройки → Устройства → Подключить устройство. Облачный пароль, если нужен,
вводится там же в локальной форме. Не проси пароль, код входа или сессию в чате.
Вход ограничен десятью минутами; QR-код обновляется по истечении срока.

Каждый пользователь создает собственную сессию. Состояние находится вне скилла:

- macOS: `~/Library/Application Support/church-skills/team-announce/telegram/`
- Linux: `$XDG_DATA_HOME/church-skills/team-announce/telegram/`, по умолчанию
  `~/.local/share/church-skills/team-announce/telegram/`
- Windows: `%LOCALAPPDATA%/church-skills/team-announce/telegram/`

`MCY_MUSIC_TELEGRAM_HOME` задает другой локальный каталог. Там находятся ключи
`config.json`, отдельная `personal.session` и журналы отправок. Каталог доступен
только владельцу (0700), файлы — 0600 на POSIX. Не включай их в архив скилла,
репозиторий, вывод инструментов или отчет. Не переиспользуй чужую сессию либо
сессию другого работающего приложения. Облачный пароль не сохраняется.

Прокси необязателен: поле `proxy` в локальном `config.json` или окружение
`MCY_MUSIC_TELEGRAM_PROXY`, например `socks5://127.0.0.1:10808`. Поддерживаются
SOCKS5 и HTTP. Поле `port` в `config.json` задает порт MTProto, по умолчанию 443;
при обрывах соединения можно проверить 80 с тем же обфусцированным транспортом.
Порт Telegram не является портом прокси. Не меняй системный VPN или сетевые
настройки без необходимости. Ошибка сети не означает неверный пароль.

## Подготовка отправки

Укажи точную цель: `me` для Saved Messages, `@username` или известный числовой ID
группы/личного чата. Не угадывай группу по похожему названию. Если цель не известна,
поищи точное название через `chats --query "название"`; при неоднозначности уточни
ее. Команда выводит только названия и ID групп, максимум из 200 последних диалогов.
Канал не подходит для отправки от личного имени. Форумы пока не поддерживаются:
не подменяй выбранную тему общей лентой.

Собери JSON вне репозитория после проверки программы и 🆕 по основному SKILL.md:

```json
{
  "target": "me",
  "date": "07.11",
  "topic": "Верность Богу",
  "songs": [
    {"number": "35", "title": "В тихий вечер склоняю", "new": false},
    {"number": "88", "title": "Как глубока любовь Отца", "new": false}
  ],
  "test": true
}
```

Это пример схемы, а не утвержденная программа. Для настоящего анонса `test`
опусти либо задай false. При true добавляется явная подпись теста. Скрипт принимает
от 1 до 10 песен, сохраняет порядок и повторы. Ограничение связано с ботом:
больше десяти он обрезает. Не дели большой запрос на части без согласования,
поскольку пользователь просит все номера разом.

```bash
uv run <skill-dir>/scripts/telegram_send.py prepare --input /absolute/path/announcement.json
```

`prepare` не отправляет в целевой чат. Он проверяет аккаунт и цель и общается
только с `@mcy_music_bot`:

1. `/info` → дождаться вопроса о номерах → отправить весь список одной строкой.
2. Собрать справку по всем библиотечным номерам; фоновые аудиозаписи игнорировать.
3. `/chords` → вопрос о номерах → тот же список одной строкой.
4. Нажать существующую кнопку `chords:full` («Весь текст с аккордами»), затем
   `chordmode:full:default` («По умолчанию»).
5. Дождаться полного набора картинок и сохранить ID исходных сообщений.

Справка может занимать несколько сообщений, аккорды — альбом из нескольких
картинок. «Два сообщения от бота» означает два результата запросов: пересылай
все части обоих, сохраняя порядок и группировку. Аудио, вопросы, служебные
предупреждения и старые ответы не пересылай. В целевой чат бот не вызывается:
его личный ответ пересылается от пользователя с указанием исходного автора.

Текущие названия и callback-кнопки проверены по коду `gtp-church/mcy-music`;
при изменении живого диалога проверь реальные кнопки вместо слепого нажатия.
Не посылай отдельный запрос на каждый гимн. Во время подготовки не смешивай
ручные запросы пользователя к боту с запросами скилла. Скрипт останавливается,
если обнаруживает посторонний исходящий запрос в ожидаемом ответе.

При неполной справке, отсутствии аккордов, запрете пересылки или тайм-ауте
в целевой чат ничего не отправляется. Не заменяй отсутствующий материал
самостоятельно сгенерированным. Сообщи, что не удалось получить.

Результат `prepare`: `job`, аккаунт, точный ID/название цели, HTML анонса и число
полученных частей. Для просмотра показывай сообщение с оформлением, без HTML-тегов.
Перед отправкой выполни `inspect --job JOB_ID` и просмотри **все** возвращенные
локальные `chord_images` доступным инструментом просмотра изображений. Сверь названия
и текст с программой в том же порядке, номера — если они указаны на листах,
наличие всех куплетов и аккордов,
а не одного первого куплета. Скрипт проверяет число фотографий, но не распознает
их содержимое. При неверной песне или нечитаемой картинке остановись и сообщи,
какой материал не удалось проверить. Не принимай просто совпадение количества
за доказательство правильных песен. Скачанные копии нужны только для просмотра;
в Telegram пересылаются исходные сообщения бота.
У аккордового листа может быть другое краткое название той же песни: сопоставляй
текст и справку бота, не подменяя автоматически выбранное название в анонсе.

Если разрешение на отправку уже получено и данные совпадают с разрешенными,
продолжай без лишнего вопроса. Иначе сначала покажи конкретный анонс и цель.

## Отправка и повторный запуск

```bash
uv run <skill-dir>/scripts/telegram_send.py send --job JOB_ID
```

`send` повторно проверяет исходные сообщения бота, затем последовательно отправляет
анонс, пересылает справку и пересылает аккорды. Моноширинные номера передаются
настоящими сущностями Telegram, а не буквальными обратными кавычками. Альбом
пересылается целиком. В супергруппах явно задается личность пользователя, чтобы
не унаследовать отправку от канала или анонимного администратора.

Журнал сохраняет ID каждой доставленной части. Завершенный job при повторе
не отправляется заново. Если результат вызова неизвестен, в журнале остается
`uncertain`: не повторяй автоматически и не создавай новый job для обхода этой
проверки. Сначала проверь фактические сообщения в целевом чате и сообщи пользователю
результат. После полной доставки новая правка программы требует новой подготовки.
Подготовка действует сутки; после этого собери актуальные материалы заново.

При `FloodWait` скрипт сохраняет `retry_at` в локальном `cooldown.json` и не делает
новых запросов до указанного срока. Не обходи паузу новым job или другой сессией.

Ссылку на сообщение можно дать для группы, если Telegram ее поддерживает.
Для Saved Messages достаточно подтвердить доставку и количество частей;
не придумывай публичную ссылку.

Первичные источники: [авторизация Telegram](https://core.telegram.org/api/auth),
[QR-вход](https://core.telegram.org/api/qr-login),
[Telethon: методы клиента](https://docs.telethon.dev/en/stable/modules/client.html).
